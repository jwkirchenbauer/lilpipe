# Presentation repair, comparison-v2

This frozen profile fixes presentation only. It preserves comparison-v1, its outputs, all numerical caches, source validation and shared plotting limits. No real study figure is rendered during preparation; tests use small synthetic canvases and suppress image writes.

The parent-reviewed allocated CPU entry is `bash -i source/comparison-v2/run.sh RUN`, with an absolute main-study path. `launcher-plan.json` contains exact 20-minute pdebug/guard launcher argv for review; preparation does not call the launcher or submit it. The entry masks GPUs, uses a private Matplotlib cache, checks the frozen manifest, and requires all scientific completion gates. Its own `status/presentation-layout-v2.json` becomes complete only after both stages succeed. Outer scheduler completion is not a substitute for this status and artifact validation.

First, `paired_layout.py` reads the unchanged canonical checkpoint comparison module. All four matched pairs must have complete validated training, native surfaces, benchmarks and profiles; the existing canonical checkpoint-report validation must be complete. The existing `checkpoint-comparisons/final` must contain exactly 40 nonempty PNG/PDF images. Both the original-layout archive and new publication provenance must be absent.

Copied display labels are wrapped near 30 columns; drawn titles place the attack/center line separately at 9-point size. The paired global header is raised slightly within its existing top margin to clear the wrapped text; its colorbar and panel layout remain unchanged. The canonical surface-data, surface-render and trajectory-render functions remain unchanged. Exact surface-data digests before/after label wrapping must agree, including coordinates, values, center offsets and common color/z limits. Cameras and coordinate bounds are untouched. Original and replacement image hashes are recorded.

All four pairs×four surface families plus trajectories are rendered in a hidden staging directory. Only after the full new 40-image set passes title checks does the worker atomically rename the original directory to `checkpoint-comparisons/layout-v1-original` and install the staged directory at the original `checkpoint-comparisons/final` path. Installation failure restores the original directory. These are two ordered directory renames, with a brief publication window between them; final consumers must wait for the completed job. The archive is never overwritten. `checkpoint-comparisons/layout-v2-publication.json` records original/new hashes and label-only provenance. Numeric CSV/JSON, reports, validations, and old control-study outputs are not changed.

Second, the aggregate renderer writes the new immutable `aggregate-comparison-v2/final` directory. A common physical layout helper reserves a separate colorbar axis to the right of every panel, plus fixed margins for the figure header, top-row titles, ticks and axis labels. It covers the fixed 1×5 families and three/four/seven-row×five-column matrices. It changes figure geometry only; grid values, axes, contour levels, shared CE ranges and all validation/data definitions are unchanged.

`scientific-equivalence.json` proves exact AST equality of every original non-rendering function. After removing only approved layout statements and normalizing the output directory string, the entire aggregate module AST matches v1. The paired renderer uses the existing frozen canonical functions and records exact runtime data-equivalence hashes before any publication. `tests-aggregate-layout.log` retains the original eight numerical fixtures and the synthetic drawn-bounds checks; `tests-paired-layout.log` covers wrapped titles, unchanged physical/data values, original archiving and rollback.

The paired publication is one-time. If a later aggregate-only retry is needed, inspect the preserved archive/provenance and invoke the frozen aggregate script separately only after reviewing its existing-output guard; do not rerun the complete wrapper against an existing archive. No model evaluations or scientific measurements are needed for presentation repair.
